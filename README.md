## :dart: O guia para alavancar a sua carreira

> .NET é a plataforma de desenvolvimento open source e multiplataforma da Microsoft (Windows, Linux, macOS): o runtime, o SDK e as bibliotecas que sustentam aplicações web com ASP.NET Core, acesso a dados com Entity Framework Core, interfaces web interativas com Blazor, apps mobile/desktop com .NET MAUI e sistemas distribuídos em nuvem com .NET Aspire. É a base de boa parte do back-end corporativo do Brasil — bancos, fintechs, seguradoras e empresas que rodam no ecossistema Microsoft/Azure. Este guia reúne documentação, cursos, livros, canais, ferramentas e comunidades focados na **plataforma .NET** (ASP.NET Core, EF Core, Blazor, MAUI, Aspire, arquitetura e deploy) — para a linguagem C# em si, veja o [Guia de C#](https://github.com/arthurspk/guiadecsharp). Os recursos em português e gratuitos vêm primeiro em cada seção, e todo link foi verificado. Use-o como apoio para os seus estudos, no seu ritmo, e não como uma lista que precisa ser vencida de uma vez.

## 🗺️ Roadmap

- [Microsoft Learn — Treinamentos de .NET](https://learn.microsoft.com/pt-br/training/browse/?products=dotnet) — Catálogo oficial com todos os módulos e trilhas de aprendizagem de .NET, filtráveis por nível.
- [Build web APIs with ASP.NET Core — módulo oficial](https://learn.microsoft.com/pt-br/training/modules/build-web-api-aspnet-core/) — Trilha oficial da Microsoft para criar sua primeira Web API do zero.
- [Introdução ao .NET — Get started](https://learn.microsoft.com/pt-br/dotnet/core/get-started) — Página oficial de início: como instalar o SDK e rodar o primeiro projeto ASP.NET Core.
- [roadmap.sh — ASP.NET Core Roadmap](https://roadmap.sh/aspnet-core) — Roteiro visual e interativo da comunidade para quem quer virar back-end com ASP.NET Core.
- [roadmap.sh — Backend Roadmap](https://roadmap.sh/backend) — O caminho completo de back-end em que o ASP.NET Core se encaixa, com bancos de dados, APIs e deploy.
- [Política de suporte do .NET (LTS/STS)](https://dotnet.microsoft.com/pt-br/platform/support/policy/dotnet-core) — Página oficial com o calendário de versões e por quanto tempo cada uma recebe suporte — essencial para escolher em qual versão construir.
- [dotnet/core — Roadmap e releases](https://github.com/dotnet/core) — Repositório oficial com o calendário de lançamentos, notas de cada versão e discussões sobre o futuro da plataforma.

**Trilha resumida** (siga na ordem; cada etapa tem recursos nas seções abaixo):

1. **Base** — instale o [.NET SDK](https://dotnet.microsoft.com/pt-br/download) e entenda a diferença entre .NET (multiplataforma, atual) e o antigo .NET Framework (só Windows).
2. **Web com ASP.NET Core** — Minimal APIs ou controllers, roteamento, middlewares e injeção de dependência nativa.
3. **Acesso a dados** — Entity Framework Core para mapear classes C# em tabelas de banco de dados, migrations e LINQ.
4. **Interfaces** — Blazor para páginas web interativas em C# (sem escrever JavaScript) ou .NET MAUI para apps mobile/desktop nativos.
5. **Testes e qualidade** — xUnit para testes automatizados, análise de código com os analisadores do Roslyn.
6. **Comunicação entre serviços** — APIs REST, gRPC para chamadas de alta performance e SignalR para comunicação em tempo real.
7. **Observabilidade e resiliência** — logging estruturado com Serilog, políticas de retry com Polly, métricas e tracing.
8. **Nuvem e orquestração** — containers com Docker, .NET Aspire para orquestrar aplicações distribuídas localmente e deploy na Azure ou em Kubernetes.

**Por onde começar:**

1. **Instale o [.NET SDK](https://dotnet.microsoft.com/pt-br/download)** (versão LTS) e o [Visual Studio Code](https://code.visualstudio.com/) com a extensão [C# Dev Kit](https://marketplace.visualstudio.com/items?itemName=ms-dotnettools.csdevkit), ou o [Visual Studio Community](https://visualstudio.microsoft.com/pt-br/), gratuito.
2. **Crie sua primeira Web API** seguindo o tutorial oficial [Criando sua primeira Web API com ASP.NET Core](https://learn.microsoft.com/pt-br/aspnet/core/tutorials/first-web-api).
3. **Aprenda Minimal APIs**, o jeito moderno e enxuto de expor endpoints HTTP no ASP.NET Core, lendo a [visão geral oficial](https://learn.microsoft.com/pt-br/aspnet/core/fundamentals/minimal-apis/overview).
4. **Conecte um banco de dados** seguindo o tutorial [Introdução ao Entity Framework Core](https://learn.microsoft.com/pt-br/ef/core/get-started/overview/first-app).
5. **Experimente uma interface web com Blazor** no [tutorial oficial de introdução](https://dotnet.microsoft.com/pt-br/learn/aspnet/blazor-tutorial/intro), sem precisar escrever JavaScript.
6. **Assista a um curso completo em vídeo:** a [Formação ASP.NET Core](https://balta.io/cursos/formacao-aspnet-core) do balta.io, ou o canal [Nick Chapsas](https://www.youtube.com/@nickchapsas) em inglês.
7. **Construa uma API real** aplicando boas práticas de arquitetura com o [Clean Architecture Template](https://github.com/jasontaylordev/CleanArchitecture) ou estudando o [eShop](https://github.com/dotnet/eShop), a aplicação de referência oficial da Microsoft.
8. **Publique um projeto no GitHub** — isso mostra domínio prático de ASP.NET Core, EF Core e organização de código, o que o mercado brasileiro valoriza tanto quanto certificação.

Seu primeiro endpoint em 30 segundos:

```bash
dotnet --version                  # confirme que o SDK do .NET está instalado
dotnet new webapi -o minha-api --use-minimal-apis
cd minha-api
dotnet run                        # compila e sobe a API localmente
```

## 🤖 IA na prática

O ecossistema .NET tem hoje um caminho direto entre "construir a aplicação" e "adicionar IA a ela": a própria Microsoft mantém SDKs oficiais para integrar LLMs a apps ASP.NET Core, Blazor e MAUI. Use a IA como **tutor e revisor**, não como piloto automático.

**Para aprender**
- Cole um erro real do ASP.NET Core (ex.: uma exceção de injeção de dependência ou de migration do EF Core) junto com o trecho de código e peça: *"explique a causa e mostre a forma correta de corrigir, respeitando as boas práticas do ASP.NET Core"*.
- Peça para **explicar um conceito com um exemplo executável**: middleware, injeção de dependência, migrations do EF Core, Minimal API vs Controller. Depois rode o exemplo em um projeto `dotnet new` local para confirmar.
- Peça **exercícios com gabarito** sobre o tópico que está estudando (rotas, autenticação com JWT, relacionamentos no EF Core) e resolva antes de olhar a resposta.
- Peça para revisar uma API sua e sugerir onde faltam tratamento de erros, validação de entrada ou paginação — três pontos que iniciantes costumam esquecer.

**Para trabalhar**
- Use o [GitHub Copilot](https://docs.github.com/pt/copilot) (integrado ao Visual Studio, VS Code e Rider), o [Cursor](https://cursor.com/) ou o [Claude Code](https://code.claude.com/docs/en/overview) para: escrever testes com xUnit, gerar migrations do Entity Framework Core, criar DTOs e mapeamentos com AutoMapper, e revisar pull requests.
- Depois de **cada** sugestão aceita, rode `dotnet build` e `dotnet test`. Se o código só compila desabilitando `nullable` ou ignorando warnings, a sugestão provavelmente está errada.
- Peça sempre a versão-alvo: "ASP.NET Core 10, EF Core 9, Minimal APIs". Sem isso a IA mistura sintaxes de versões diferentes do framework.

**Limites e boas práticas**
- A IA **inventa métodos e pacotes NuGet** que não existem, ou confunde APIs do .NET Framework antigo com o .NET moderno (multiplataforma). Confirme sempre na [documentação oficial](https://learn.microsoft.com/pt-br/aspnet/core/) e no [NuGet](https://www.nuget.org/).
- Ela tende a ignorar tratamento de exceções, `IDisposable`/`using` e o uso correto de `DbContext` (ex.: reaproveitar o mesmo `DbContext` entre requisições). Peça explicitamente por tratamento de erros e gerenciamento correto de recursos.
- Cuidado com sugestões de SQL concatenado dentro de uma consulta — é porta para SQL Injection; use sempre o Entity Framework Core ou parâmetros.
- Não cole código proprietário, segredos (connection strings, chaves de API, secrets do `appsettings.json`) ou dados de clientes em ferramentas sem a política da sua empresa.
- Entenda o que você aceita: em entrevista e em produção, o código é seu.

**O ecossistema .NET é "IA-first" dentro do próprio ecossistema Microsoft.** Os SDKs abaixo permitem construir aplicações .NET que consomem ou incorporam LLMs:

- [GitHub Copilot — documentação (PT-BR)](https://docs.github.com/pt/copilot) — Assistente de código integrado ao Visual Studio, VS Code e Rider; gratuito para estudantes e com plano free limitado.
- [GitHub Copilot (visão geral)](https://github.com/features/copilot) — Página oficial do Copilot, com os planos disponíveis e como ativar em cada editor.
- [Semantic Kernel](https://github.com/microsoft/semantic-kernel) — SDK oficial da Microsoft para integrar LLMs, agentes e plugins em aplicações .NET.
- [Microsoft.Extensions.AI](https://learn.microsoft.com/pt-br/dotnet/ai/microsoft-extensions-ai) — Abstração oficial e unificada da Microsoft para consumir modelos de IA a partir de qualquer app .NET.
- [Crie um app de chat com IA em .NET (tutorial oficial, Azure OpenAI)](https://learn.microsoft.com/en-us/dotnet/ai/quickstarts/build-chat-app) — Guia oficial passo a passo para construir uma aplicação .NET que conversa com um modelo da OpenAI/Azure OpenAI.
- [openai-dotnet (SDK oficial da OpenAI)](https://github.com/openai/openai-dotnet) — Biblioteca oficial da OpenAI para .NET, mantida em parceria com a Microsoft.
